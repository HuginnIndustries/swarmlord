● You've got a 10-minute walkthrough for this exact question already in the
  repo: GUIDE.md. The high-level shape:

  uv sync --dev                                            # one-time install
  uv run swarmlord --help                                  # see all commands
  uv run swarmlord new my-thing --title "..." --summary "..."   # scaffold a 
  packet
  uv run swarmlord list                                    # what's on disk
  uv run swarmlord next                                    # what's dispatchable
  uv run swarmlord render my-thing                         # build the prompt
  uv run swarmlord run my-thing --runner manual            # execute
  uv run swarmlord promote my-thing --to discovery         # advance the stage
  uv run swarmlord log my-thing                            # see run history
  uv run swarmlord extract my-thing --target ../my-thing   # ship as standalone 
  repo

  The mental model: each project is a "packet" under projects/<slug>/. You move
  it through stages idea → discovery → spec_ready → build_ready → extracted → 
  archived, and the CLI gates promotions on typed predicates defined in the
  packet's workflow/WORKFLOW.md.
